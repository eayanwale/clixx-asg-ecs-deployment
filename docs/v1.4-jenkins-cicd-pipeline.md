## What Changed

Ported the Jenkins/Terraform pipeline pattern built for Blog (STC15-1695) to the Clixx stack. `stack-aut-Clixx/Jenkinsfile` runs `init` → `plan` → `apply`/`destroy` against `stack-aut-Clixx`, posts status to Slack, and prints the deployed Clixx URL.

---

## Pipeline Structure

Same shape as the Blog pipeline:

- **Parameter:** `ACTION` (`apply` | `destroy`)
- **Determine action:** sets `DEPLOYING` / `TEARING DOWN` label for Slack messages
- **Terraform Init:** `terraform init -upgrade` in `stack-aut-Clixx`; Slack notification (yellow) on start
- **Terraform Plan:** `terraform plan -out=tfplan -input=false` (`-destroy` appended when tearing down)
- **Terraform Apply** (`when ACTION == apply`): applies the plan, reads `clixx_url` from Terraform output, Slack notification (green) with the URL
- **Terraform Destroy** (`when ACTION == destroy`): `terraform destroy -auto-approve`, Slack notification (red)
- Terraform resolved via Jenkins tool config (`terraform-1.10`)

---

## Clixx-Specific Fixes Needed to Get Apply Passing

Reusing the pipeline surfaced two Clixx-only infra issues that Blog didn't have:

- **Launch template apply failure:** block device mappings in `launch-template.tf` conflicted with the source AMI's actual block size, failing `terraform apply`. Commented out the block device mappings so the AMI's native block config is used instead (`eb35997`).
- **ASG instances getting public IPs:** the launch template was assigning public IPs to instances in the Auto Scaling Group. Set `associate_public_ip_address = false` so ASG instances stay private, consistent with the intended network design (`de76988`).

---

## Result

Triggering the Jenkins job with `ACTION=apply` provisions the Clixx stack end-to-end (VPC/networking, RDS, EFS, ASG/launch template, ALB) without the block-device or public-IP issues, and reports the live URL in Slack; `ACTION=destroy` tears it down.
