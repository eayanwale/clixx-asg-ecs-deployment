# v1.1 — RDS Snapshot Identifier Fix

**Date:** 2026-06-02
**Commit:** `241927b`

---

## Issue

After the initial Clixx deployment (`c17ff72`), running `terraform plan` produced an error because the RDS snapshot data source couldn't find a snapshot named `clixx-working-snapshot`.

The snapshot had been **manually renamed in the AWS console** to `clixx-recent-snapshot` at some point before this Terraform stack was written. Terraform had no way to know about this rename — it just tried to look up the old name and got a not-found error.

---

## Fix

Updated `db_snapshot_identifier` in `stack-Clixx/rds.tf`:

```hcl
# Before
data "aws_db_snapshot" "latest_prod_snapshot" {
  db_snapshot_identifier = "clixx-working-snapshot"
  most_recent            = true
}

# After
data "aws_db_snapshot" "latest_prod_snapshot" {
  db_snapshot_identifier = "clixx-recent-snapshot"
  most_recent            = true
}
```

---

## Lesson

When using `data "aws_db_snapshot"` to reference existing snapshots, the identifier must match exactly what's in AWS. Manual renames in the console don't update Terraform state. If the snapshot name is likely to change, consider using `db_instance_identifier` (filter by the source instance) with `most_recent = true` instead of a fixed snapshot name — that way the latest snapshot is always used regardless of what it was named.
